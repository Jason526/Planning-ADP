Planning Testeurs & Observateurs

Cycles de 4 semaines · exposition suivie sur 12 mois glissants

Agents

9 testeurs + 5 observateurs par défaut. Ajoutez, renommez ou supprimez librement.

Sites / Terminaux

Remplacez par vos vrais sites quand vous les aurez. Le Terminal 2E est marqué car son volume passagers reste élevé de 21h à 24h (contrairement aux autres sites) — la rotation doit y être particulièrement soignée.

Prestataires

Chaque site est rattaché à un prestataire. Un même prestataire peut couvrir plusieurs sites.

Tranches horaires (référence)

Volume passagers indicatif par créneau — utilisé pour information seulement. La génération répartit les missions à parts égales entre les 5 créneaux, quel que soit le volume, afin de garder un risque d'exposition faible.

Seuils de risque d'exposition

Repris de votre grille. Passages/site et missions/prestataire s'appliquent sur une fenêtre glissante de 12 mois ; le créneau horaire et la reconnaissance s'appliquent sur le cycle de 4 semaines en cours.

Volume de missions

Générer un nouveau cycle de 4 semaines

L'algorithme attribue à chaque agent, à chaque mission, le site le moins visité par lui sur les 12 derniers mois (et dont le prestataire est le moins sollicité par lui sur 12 mois), en faisant tourner les 5 créneaux horaires de façon égale sur le cycle. Chaque génération ajoute un nouveau cycle de 4 semaines à l'historique — les cycles précédents ne sont pas effacés, ils continuent de compter dans la fenêtre glissante de 12 mois.

Planning détaillé

Une ligne par mission. Vous pouvez réattribuer manuellement un site ou signaler un incident de reconnaissance directement dans le tableau.

Risque d'exposition par agent

Passages/site et missions/prestataire sont calculés sur une fenêtre glissante de 12 mois (comme votre grille). Le créneau le plus répété et la reconnaissance sont calculés sur le cycle de 4 semaines le plus récent.

Export / Import JSON

Pour partager le planning entre plusieurs managers sans backend commun : exportez un fichier JSON, envoyez-le, l'autre manager l'importe.

Publier sur GitHub Pages

1. Sur github.com, ouvrez votre dépôt (ou créez-en un nouveau, public).
2. Cliquez Add file → Upload files, glissez ce fichier et renommez-le index.html (à la racine, ou dans un sous-dossier).
3. Validez le commit (Commit changes).
4. Allez dans Settings → Pages, section Build and deployment : choisissez la branche main et le dossier / (root), puis Save.
5. Après 1–2 minutes, l'URL s'affiche en haut de cette même page (https://votre-pseudo.github.io/nom-du-depot/).
6. Pour toute mise à jour : remplacez le fichier via Add file → Upload files à nouveau, ou éditez-le en ligne avec l'icône crayon.
Données stockées uniquement dans ce navigateur (localStorage). Utilisez l'export JSON pour synchroniser entre managers ou postes.
